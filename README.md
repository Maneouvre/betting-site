# MatchMate demo

MatchMate is a PHP, MySQL, HTML, CSS, and browser-JavaScript prototype for football peer bets and Konami eFootball 1v1 matches.

## Run locally with XAMPP

1. Start **MySQL** in the XAMPP Control Panel.
2. In phpMyAdmin, import `schema.sql`. It creates the `matchmate` database and tables.
3. Copy the project folder into `C:\xampp\htdocs\matchmate`, or start PHP's built-in server from this folder:

   ```powershell
   php -S 127.0.0.1:8000
   ```

4. Visit `http://127.0.0.1:8000`.
5. Register a player account. The generated account number is used with the password to sign in.
6. Configure `DB_HOST`, `DB_NAME`, `DB_USER`, and `DB_PASS` as environment variables on non-local servers. Public requests are refused when these are missing; local XAMPP and CLI use localhost defaults. Never commit credentials.
7. The administrator dashboard has its own protected page at `http://localhost:8000/admin.php` (or `/matchmate/admin.php` under XAMPP). First sign in on the player site with your administrator account; an admin-only dashboard link appears in the header. The PHP page checks the signed-in account's database role before returning the dashboard. To enable your own registered account, promote it in phpMyAdmin:

   ```sql
   UPDATE users SET role = 'admin' WHERE account_number = 'MM-2026-12345';
   ```

   Sign out and sign back in to refresh the account role, then use the **Admin dashboard** link or open `/admin.php`.

The registration form records acceptance of [Terms & Conditions](terms.html) and the terms version. If upgrading an existing database, apply the additive migration below before starting the updated API. Existing accounts are preserved; their acceptance fields remain `NULL` because earlier acceptance cannot be assumed.

```sql
ALTER TABLE users
  ADD COLUMN terms_accepted_at DATETIME NULL,
  ADD COLUMN terms_version VARCHAR(32) NULL;

ALTER TABLE bets
  ADD COLUMN paid_from_registered_number TINYINT(1) NOT NULL DEFAULT 0 AFTER user_paid;

ALTER TABLE bets
  ADD COLUMN payment_sender_name VARCHAR(100) NULL AFTER paid_from_registered_number,
  ADD COLUMN team_name VARCHAR(100) NULL AFTER selection,
  ADD COLUMN team_strength SMALLINT UNSIGNED NULL AFTER team_name;

ALTER TABLE bets
  MODIFY status ENUM(
    'open', 'matched', 'awaiting_payment', 'awaiting_code', 'paid',
    'won', 'lost', 'tie', 'refunded', 'completed', 'cancelled'
  ) NOT NULL DEFAULT 'open';
```

The default database settings are for a local XAMPP installation (`127.0.0.1`, database `matchmate`, user `root`, blank password). Set `DB_HOST`, `DB_NAME`, `DB_USER`, and `DB_PASS` in the PHP server environment when using different local database settings. Never deploy the local defaults to a public server.

## Privacy and deployment security

- Room codes are returned only to an authenticated participant for their matched bet, and only after both players' payment references are approved. Admin access is role-checked server-side. Do not put payment references, room codes, or database credentials into browser files, screenshots, issues, or logs.
- Apache deployments should retain `.htaccess` and enable `AllowOverride` so config, SQL, dotfiles, backups, and `.git` are not served and the security headers apply. PHP's built-in development server ignores `.htaccess`; do not use it as a public host. Keep the database outside the web root where possible and use HTTPS.
- Browser assets (`index.html`, `app.js`, and `styles.css`) must be delivered to users and are not secret. `.gitignore` does not remove already tracked files or hide a repository. The linked GitHub repository is currently public; only a repository owner can change its visibility to private in GitHub repository Settings → General → Danger Zone → Change repository visibility. Until that is done, assume all tracked source files are public.

## Demo limits

- Fixtures are illustrative sample data generated by the PHP endpoint, not a live football schedule.
- Matchmaking works between accounts using the same installation and database. Stakes are integer KES amounts of at least KES 50. Football matches require the same fixture, equal stakes, and different predictions; identical picks such as Arsenal/Arsenal or Draw/Draw do not match. eFootball matches require equal stakes.
- Football bets close 30 minutes before kick-off. After a match is found, the admin must request payment; eFootball players then have five minutes to submit their M-Pesa transaction reference. Football references must be submitted before the 30-minute cutoff.
- The admin dashboard has a separate open-request panel showing player, stake, fixture and pick, or eFootball squad name and strength. Matched players and payment review appear separately.
- Each eFootball request requires a squad name and team-strength rating as shown in-game (integer from 1 to 9,999). This value is self-reported and shown in the admin requests panel.
- Players are matched before any payment step. The admin dashboard groups both players, their equal stakes, payment references, and approval states in one row. A request updates both player dashboards; WhatsApp/SMS links open prefilled messages but are not sent automatically.
- Each player submits a Safaricom reference and sender name and confirms the transfer came from their registered M-Pesa number. The admin sees those details and must compare them with the actual transaction record; this is manual, not automatic Safaricom verification. The prototype cannot block an external M-Pesa transfer. For eFootball, neither player can submit or view a room code until both payment references are approved. After that, the code is visible only to the two matched players and admins; the API scopes player access to their own matched bet.
- Each eFootball round is one game. Both players submit their result once; compatible reports automatically identify the agreed winner, while conflicting reports are resolved by an admin. Room codes are not a Konami result feed.
- The same players can start another separate round after the previous result is recorded, even while its payout is still due. A new stake, payment approval, and fresh eFootball room codes are required. The player dashboard totals stakes, pending payouts, and payouts manually marked sent.
- A 10% manager fee is rounded to the nearest whole KES and deducted from the two-player matched pot after a winner is confirmed; the estimated Send Money fee is also deducted when calculating the displayed final payout (KES 90 from two KES 50 stakes). Ties are refunded without the manager fee. Payouts and refunds are manual.
- Send Money fee estimates use the bands supplied by the user (KES 0 for KES 1–100, KES 7 for KES 101–500, and so on through KES 50,001–250,000). The estimate is deducted from the remaining pot when calculating the payout. These rates could not be independently verified as the official Safaricom 2026 tariff; Till/Buy Goods and amounts above KES 250,000 are not estimated. Confirm the current Safaricom tariff before relying on the displayed estimates.
- WhatsApp and SMS links open a prefilled message; the site does not send messages.
- This prototype is not a regulated betting service. It does not provide live fixtures, payment processing, independent result verification, or production-ready fraud controls. Use secure hosting, HTTPS, restricted database credentials, regulatory review, payment-provider integration, and verified result feeds before any real-money use.
